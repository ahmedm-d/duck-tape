# Acceptance matrix

This is the release mapping for the original 14 journeys. The [approved Task 14 plan](superpowers/plans/2026-11-14-steward-completion.md#task-14-reproducible-startup-independent-review-and-final-acceptance) and [current verification report](VERIFICATION.md) define scope. Linked historical evidence proves its recorded run, not a fresh integrated release. The complete actual model corpus remains a required gate; service availability, sample inference, deterministic provider transports and screenshots cannot substitute for it.

## Reproduce the tiers

Install the locked Python/frontend dependencies using the documented [startup instructions](../README.md). Run from the repository root with that Python environment active:

```powershell
python scripts/acceptance.py --tier deterministic
python scripts/acceptance.py --tier sandbox
python scripts/acceptance.py --tier live --url http://127.0.0.1:8767
python scripts/acceptance.py --tier all --url http://127.0.0.1:8767
```

The prepared developer checkout also supports `PYTHONPATH=vendor-current` and `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`. The CLI loads the same literal project `.env` as `run.py`; explicit process environment wins. It does not install models, images, dependencies or browsers, change security settings, or start paid services. Configure the real provider/embedding model and prepare the pinned Docker images before requesting the corresponding tier. Provider calls run sequentially; do not launch a second live acceptance run against the small CPU inference server.

Install Chromium once with `npx playwright install chromium` from `frontend/`, or set `STEWARD_BROWSER_EXECUTABLE` to an existing permitted Chromium/Chrome executable. CI installs Chromium with its operating-system dependencies. A browser launch failure is required-gate failure, never evidence of a passing UI.

The live browser suites require an already running dedicated local application, for example `python run.py --port 8767` with a separate `STEWARD_DATA_DIR`. `--url` permits only an explicit loopback URL without credentials or a path. The sample browser script resets sample data in that application; use a test workspace. Fixture browser tests start the existing Vite test server themselves and require no running backend.

| live | `tests/live/test_provider_live.py`, `test_retrieval_live.py`, `scripts/evaluate_retrieval.evaluate(output)`, `test_imported_workflows.py`, `scripts/evaluate_models.py --driver scripts.qualification_driver:driver`, portable actual ZIP-import Playwright journey, `npm run test:sample` | Actual provider/embedding checks, measured retrieval modes, generic Python/TS pipelines and full 12-task driver. Each invocation writes a unique directory under `data/acceptance/` (override its parent with `--output`). `report.json` contains schema version, tier, aggregate `passed|failed|blocked`, completion state, redacted capability facts, exact argv/cwd, per-gate status/exit/duration and artifact paths. JUnit, Playwright JSON, logs, retained browser failures, retrieval measurements and model qualification output are linked from gate records. Pending required gates stay blocked in partial reports. Exit codes are **0 passed, 1 failed, 2 blocked**; failure takes precedence when failures and blockers coexist. A successful process without its required machine-readable evidence cannot pass. Model qualification additionally requires an actual application-qualification artifact with 12 records and `qualified: true`; no schema smoke is used. Existing artifacts are never reused as current-run evidence, and evidence directories are not automatically deleted.

Fast CI runs only the deterministic tier and uploads its artifacts even on failure. Sandbox and live tiers must be requested separately on a permitted runner. The CLI's focused construction/accounting tests are [test_acceptance_script.py](../tests/test_acceptance_script.py); their fake command runner verifies the CLI itself and is not counted as service acceptance.

## Release interpretation

The [security](evidence/security-completion-review.md), [functional/AI](evidence/functional-ai-completion-review.md), [rendered UX](evidence/ux-completion-review.md) and [fresh final acceptance](evidence/final-acceptance-review.md) reports retain reproduced findings and scoped rechecks. No full-live release endorsement follows from this matrix alone. In particular, a passing corpus does not add untested live dependency-remediation/research journeys, broad language support, production authentication, or guaranteed future coding reliability. Review the remaining external/live gaps before calling the original complete release accepted.

The real provider settings preview test currently names its recorded 3B model explicitly; generic live CLI browser execution selects the portable ZIP-import journey instead. Its separate settings evidence is retained in the UI report. The completion-review browser suite is intentionally dedicated to its prepopulated preview and is not silently treated as a clean-checkout generic suite.
